## 4–5. Battery power and sensor coverage

`rigpulse-windows/src/battery.rs` queries each system battery's tag, information and `IOCTL_BATTERY_QUERY_STATUS`. Signed `BATTERY_STATUS.Rate` is converted from mW to W; voltage from mV to V. Positive power must agree with the charging state, negative power with discharging. Unknown sentinel, contradictory direction, relative units, unavailable status and absent batteries return unavailable. A genuine zero remains zero. All packs must provide a valid rate before a net multi-battery total is shown. Chemistry, voltage, capacity, health and cycle count are sourced from firmware/Windows.

The Battery page distinguishes net battery power from charger rating and total laptop power. It records at most 720 valid five-second samples for an optional signed history graph. Unsupported rate/status queries back off for 60 seconds. Charging/discharging/zero/unknown/relative/multi-pack interpretation is tested in isolation; the host Windows power API was read successfully. Physical discharge/charge transitions and multi-battery hardware have not all been exercised.

## 8. Network data sources and history

New `rigpulse-network` owns Windows IP Helper integration and bounded workers. `GetAdaptersAddresses` reads interface/link/address/gateway/DNS/MAC metadata; `GetIfEntry2` reads cumulative octets; `GetBestInterfaceEx` selects a single route rather than summing physical and VPN interfaces. Throughput uses byte differences divided by elapsed monotonic time. Counter regressions and adaptor changes start a new baseline. Mbps uses bytes/s × 8 / 1,000,000; optional decimal B/s, KB/s and MB/s are labeled explicitly.

Sampling is every two seconds, with a maximum 1,801-point/one-hour history and a four-snapshot channel. Discovery is refreshed every 30 seconds or manually. Pause freezes displayed history while sampling continues. Recent totals sum actual counter deltas over the selected complete measured intervals; session totals are separately labeled. Missing/reset/disconnected samples break the chart segment. Link speed is explicitly distinguished from live traffic and internet test results. The traffic includes LAN and other applications on that adaptor. Local identities are hidden by default and never enter the network-free report model. Native Wi-Fi SSID/signal uses `WlanQueryInterface` only after a manual action with local-identity visibility enabled; Windows location/policy denial is displayed, without bypassing it.

## 9. Speedtest methodology: Ookla

The Rust `ookla` module wraps the official Windows x64 Speedtest CLI 1.2.0; there is no invented Ookla Rust SDK. The publisher explicitly documents wrapping its CLI from other languages. The proprietary binary is not redistributed in RigPulse's MSI/ZIP. After the user accepts the displayed Ookla EULA/terms/privacy and starts a test, the exact publisher archive is downloaded over HTTPS from `install.speedtest.net`. Archive SHA-256 `13e3d888b845d301a556419e31f14ab9bff57e3f06089ef2fd3bdc9ba6841efa` and executable SHA-256 `c73c4ac2a7cdc48829fe0f9d7ec91ca41c8b434490d4eb3205aad69c7aa3b921` are pinned. The publisher documentation is retained alongside the optional download. No PATH search, shell command or user-supplied executable is used.

The child runs hidden and streams bounded JSONL, with concurrent bounded stderr reading. GUI progress comes from actual Ookla stages/percentages. The final successful result supplies measured server, download/upload, latency and optional jitter/packet loss; bytes/s is converted to Mbps. Missing values, including missing transfer totals, stay unavailable. Cancellation kills/reaps only this owned child. Normal window closing requests network cancellation and keeps the GUI alive until the worker reports completion, then closes automatically; a regression test covers this behavior. Runtime is capped at 120 seconds; reported transfer counters trigger termination above 512 MiB. This is a sampling guard, not an exact wire-byte cap: traffic between progress events/protocol overhead may exceed it; if the CLI omits counters only the time limit applies. Incomplete, timed-out, cancelled, malformed or failed runs never produce a fabricated final result. High-speed tests can hit the transfer guard before completing.

The official archive/hash/extraction and output parsing were tested without running a bandwidth test or accepting the user's license. A complete real Ookla test remains a user-triggered runtime check. Ookla's supplied CLI terms restrict use to personal/non-commercial use; other distribution or commercial SDK usage needs an appropriate publisher arrangement.

Sources: [Ookla CLI](https://www.speedtest.net/apps/cli), [publisher CLI documentation page](https://speedtest-static-staging.speedtest.dev/apps/cli), and `speedtest.md` inside the verified official download.

## 10. Ping

Native `IcmpSendEcho` / `Icmp6SendEcho2` measures ten manually requested IPv4/IPv6 echo attempts, one-second timeout each, with cancellable half-second spacing. DNS has a five-second UI-worker deadline and at most one outstanding OS resolver thread. Validation accepts IPs/hostnames, not shell commands/URLs. Only successful echo replies supply RTT; failures/timeouts count toward packet loss. Jitter is mean absolute difference between adjacent successful attempts, with no interpolation across loss. No reply yields unavailable RTT/jitter, not 0 ms. Native IPv4 and IPv6 loopback checks passed outside the restrictive sandbox.

## 11. Public IP / ISP / ASN

Manual, opt-in HTTPS requests use `api64.ipify.org` for the observed public IP family and `ipwho.is` for explicit ISP, organisation, ASN and country fields. No serials, hardware/app inventory or MAC are sent. One-hour in-memory cache/cooldown, short timeouts, no redirects, 64 KiB response bound and clear provider-failure states limit requests. There is no automatic lookup or persisted/exported public/local network identity. IPv4 or IPv6 is shown only if actually observed; the other family is not invented. ISP/ASN/geolocation are provider metadata and can be unavailable or imprecise, especially with VPNs. ipwho.is documents 1,000 free requests/day/client IP; the provider can change policy or reject shared-IP traffic. Sources: [API documentation](https://ipwhois.io/documentation), [terms](https://ipwhois.io/terms), [privacy](https://ipwhois.io/privacy).

## 12–14. Driver ETA, WUA and installation

WUA uses a dedicated COM MTA worker and Windows' configured update source/policies. Search, download and installation use official `BeginSearch`, `BeginDownload`, `BeginInstall`, job progress/abort, and matching End/CleanUp operations. Search elapsed time is displayed without invented percentage/ETA. Download progress uses actual WUA byte/percent counters and a smoothed measured byte rate; initial, unknown, regressed or stalled progress has no confident ETA. Installation uses WUA percentage when available, otherwise an indeterminate state, without a fabricated time estimate.

Download Selected, Install Selected, individual Update and Update All operate on eligible offered packages after explicit confirmation. Identity and revision are re-searched immediately before execution, classes/hardware IDs revalidated, duplicates rejected and stale consent rejected. Firmware/BIOS, unknown/critical classes and unaccepted package licenses are excluded; license acceptance is routed to Windows Update rather than silently accepted. WUA provides title/model/provider/description, size estimate, download status and reboot behavior. WUA does not supply a separate reliable driver-version property here; the actual offer title is shown, without guessing a version string. Each package result retains its WUA operation code, HRESULT and reboot flag. Device inventory and offered updates are refreshed after completion; device presence/problem-code checks are not claimed as exhaustive version certification.

Production direct installation is enabled in 0.4.0 after the user's explicit feature request. Windows administrator rights, WUA availability and organisation policy still apply. Pending reboot/busy installer checks and a per-session operation mutex prevent conflicting RigPulse installs. A separate `--driver-admin` process opened through UAC exposes Drivers only, re-searches offers and requires its own user selection/confirmation; no caller-provided package/command crosses the elevation boundary. Cancellation requests WUA abort and waits for its real result; an in-progress driver step may not stop immediately and installed packages are not rolled back. Closing is deferred during active installation. Restart Later leaves the machine running; Restart Now requires a second explicit dialog. No automated test installs drivers or restarts Windows. Physical installation/UAC acceptance/denial/partial failure/reboot still require manual recoverable-hardware validation.

Sources: [asynchronous WUA guidance](https://learn.microsoft.com/en-us/windows/win32/wua_sdk/guidelines-for-asynchronous-wua-operations), [BeginInstall](https://learn.microsoft.com/en-us/windows/win32/api/wuapi/nf-wuapi-iupdateinstaller-begininstall), [battery status](https://learn.microsoft.com/en-us/windows/win32/power/battery-status-str), [Wi-Fi access permissions](https://learn.microsoft.com/en-us/windows/win32/nativewifi/wi-fi-access-location-changes).
